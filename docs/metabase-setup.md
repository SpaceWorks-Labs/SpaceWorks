# Metabase setup (per-space and platform analytics)

SpaceWorks does not bundle Metabase. It gives each space a **read-only database login** limited to curated
views, and shows the dashboards you build in Metabase inside the staff console. **You need no account or key
from anyone**: the database login and the connection details are generated by SpaceWorks, and the embedding
secret is generated by your own Metabase. The `analytics` module must be on (it is off by default); the views
are listed in [analytics-views.md](analytics-views.md).

## 1. Run Metabase

Any Metabase works (Cloud or self-hosted). For a local test, add this to a compose file next to SpaceWorks
(it joins the dev network so the database host the app reports is reachable; adjust the network name to your
stack's, see `docker network ls`):

```yaml
services:
  metabase:
    image: metabase/metabase:latest        # pin a version for anything you keep
    ports: ["3000:3000"]
    environment:
      MB_DB_FILE: /metabase-data/metabase.db   # Metabase's own H2 store; use Postgres for production
    volumes: ["metabase-data:/metabase-data"]
    networks: [default, spaceworks]
volumes:
  metabase-data:
networks:
  spaceworks:
    external: true
    name: spaceworks_default
```

Open http://localhost:3000 and finish Metabase's first-run wizard (this creates a Metabase admin; it is
unrelated to SpaceWorks).

## 2. Create the space's read-only login in SpaceWorks

Staff console -> **Reports -> Analytics** (Space Manager, or anyone holding `view_analytics`/manage
rights; superadmin can do it too) -> **Create database login**. SpaceWorks shows **once**: host, port,
database, schema (`spaceworks_analytics`), username and password. Copy them now; only ciphertext is kept.
**Rotate** issues a new password (update Metabase after), **Revoke** removes the login. The login can read the
curated views of this space only, owns nothing and has no write or bypass rights.

## 3. Connect Metabase to Postgres with that login

Metabase -> **Admin -> Databases -> Add database -> PostgreSQL**. Fill host, port, database, user and password
from step 2. Use SSL if the database is on another network. The host shown is the address *the SpaceWorks
app* uses; for Metabase on a different network use the database's reachable address instead (in the local
compose above, the `db` service name). Under advanced options restrict **Schemas** to `spaceworks_analytics`.

## 4. Enable embedding and get the secret

Metabase -> **Admin -> Settings -> Embedding** -> enable **Static embedding** and copy the **embedding secret
key**. Build dashboards on the views (start from a saved question per view), open each dashboard -> **Sharing
-> Embed** -> **Publish**, and note its numeric id (the number in its URL).

## 5. Paste into SpaceWorks

In **Reports -> Analytics -> Connection** enter the **Metabase site URL** (`https://metabase.example.org`, no
trailing path, credentials, query or fragment), the **embedding secret** (encrypted at rest, write-only) and
the **dashboard list** (id and title for each). Staff holding `view_analytics` then see the dashboards in the
console. Each view is shown through a signed URL for one dashboard that expires after ten minutes; the secret
never reaches the browser. **Show member details** (off by default) is the only switch that lets the `members`
view carry names and e-mails.

## Platform-wide Metabase (superadmin)

Platform settings -> **Analytics** has the same screens against one separate Metabase connection. Its login
reads the `spaceworks_analytics_platform` schema: every space, never member details. Use a different
Metabase database entry (and ideally collection) from any space's.

## Check it

- A space's login must fail to read another space's rows: in Metabase's SQL editor run
  `select distinct makerspace_id from spaceworks_analytics.inventory_products;` and expect only your space.
- After Revoke, the Metabase database connection must start failing.
- Embedded dashboard blank? Check the site URL is reachable from the browser, static embedding is on and
  the dashboard is published. On static-hosting deployments (Cloudflare, Netlify, Vercel) add the Metabase
  origin to the edge setting `FRAME_ORIGINS`; Docker/nginx installs set no `frame-src` and need nothing.

Prefer Grafana, or want both? The same login and views work there: [grafana-setup.md](grafana-setup.md).

## What needs a real account

Nothing beyond Metabase itself. Hosted Metabase Cloud is a convenience, not a requirement.
