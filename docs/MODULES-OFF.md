# When a module or feature is off

This reference covers all 37 module keys and 209 feature keys. The staff console lists 208 of the feature keys: `machines.integrations` is deliberately not exposed in the browser (it has no console screen while the printer-agent integration is deferred) and is switched in the platform control plane only. Use [Modules](MODULES.md) to choose what to install and [module lifecycle](MODULES-LIFECYCLE.md) for uninstall, purge and deployment removal.

A switch keeps its stored settings and history. Re-enabling restores access only where parent modules, other required features, permissions, account state and current record eligibility also allow it. Old deadlines and expired credentials still apply. Shared screens remain available when another enabled area uses them.

Dedicated disabled APIs normally return 404. Shared module and feature guards use module_disabled and feature_disabled. Folded maintenance, repairs, To-Buy and warranty guards can use capability_disabled. Shop uses feature_off or shop_closed. Public discovery and private credential routes can return an ordinary 404. Payload and permission checks can refuse a request before its switch is evaluated.

Feature-owned reports and notifications observe their source switch. Schedules are retained and eligible work resumes under current policy. Security, retention, core accounting and settlement of money already in flight keep their separate duties. The entries below describe historical and shared-flow exceptions.

## Features

The Settings feature list groups these switches by area. Turning off a parent makes its child ineffective while retaining the child’s setting. Shared configuration editors can keep inactive values editable for later use. Switching off does not erase an obligation, an issued evidence snapshot, a finance document or an audit record.
