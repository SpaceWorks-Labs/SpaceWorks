# Environment settings

Space Works is configured through environment variables. The installer writes them into a private `.env` file
in the install directory (mode restricted to the install owner). You rarely need to edit it by hand.

## What you decide, and what has a default

The example files (`.env.example`, `.env.production.example`, `backend/.env.example`) carry only what a
deployment must decide. Everything else has a default that is correct for a server on the internet.

| You must set for a real server | Why |
| --- | --- |
| `ALLOWED_HOSTS` | Django's host check. Add every custom domain. |
| `CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS` | The website origins allowed to call the API and post forms. |
| `PUBLIC_APP_BASE_URL` | The origin used in emailed links. Blank falls back to localhost. |
| `SECRET_KEY` and the encryption keys | Generated by the installer; see [Security hardening](security.md#secrets-and-encryption-keys). |
| `DATABASE_URL` or the bundled database | Where the data lives. See [Hybrid setups](hybrid.md). |
| `AWS_S3_ENDPOINT_URL`, `AWS_S3_PUBLIC_ENDPOINT_URL`, buckets | Backend-facing and browser-facing object storage addresses. |

`DEBUG` must stay `False` off your own computer. `LOG_JSON` defaults to on when `DEBUG` is off, giving one JSON
object per log line that carries the request's `X-Request-ID`.

## Changing a setting

1. Copy `.env` somewhere safe first (`cp -p .env .env.before-change`).
2. Edit the value.
3. Apply it without changing the release: `bash scripts/apply-settings.sh`. It takes the update lock, checks
   running containers still match their local images, refreshes the Compose trust records, restarts what
   changed and probes the result. It needs Linux or WSL2.

Apply an edited `.env` this way before the next update, or the updater refuses the changed file. To show or hide
the SpaceWorks product page at the front page (`HUB_LANDING_ENABLED`, on by default), run
`bash scripts/apply-settings.sh --landing on` or `--landing off`. Control-plane
settings have their own helper, `scripts/control-plane-settings.sh`; storage, Redis and email changes use
`scripts/switch-services.sh` (see [Hybrid setups](hybrid.md)).
